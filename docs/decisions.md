# 作者の決定（docs/design-notes.md のレビューを受けて。SPEC/CONTRACT より優先する）

2026-08-23 決定。設計相談の指摘のうち採用したもの・却下したものと、その理由。

## 採用1: 正解とは「目標の音高が出たこと」。弦と指は判定していない
マイクから取れるのは周波数だけで、どの弦のどの指かは観測できない。
- 誤答時の文言を変える。「いまのは ラ線の1に聞こえたよ」は**禁止**。観測していないことを
  観測したように言っている。正しくは **「いまのは ド♯ の高さに聞こえたよ（ラ線の1の高さ）」**。
  音名が主語、運指は括弧の中の言い換え。
- 譜面の下に出す弦と指は「**このアプリが勧める運指**」であって判定対象ではないと画面に明記する。
- 結果画面でも「音高が合っていた」としか言わない。

## 採用2: ヒントは既定オフ。答えを最初から見せない
音名と弦・指を常時出すと、五線を読まずに文字を読んで弾けてしまい、鍛えたい変換
（音符 → 弦と指）を迂回する。
- 既定は**ヒントなし**。譜面だけが出る。
- **「わからない」ボタン**を1つ置く。押すと段階的に開く: 1回目＝音名、2回目＝弦と指。
  いま弾く音のぶんだけ。次の音へ行くとまた閉じる。
- **外したときは自動で1段目（音名）まで開く。**（詰まって止まるのを防ぐ）
- どの音でヒントを使ったかを記録し、結果画面に出す。上達＝ヒントなしで初回に通せた音が増えること。
- 設定で「最初からヒントを出す」も選べる（レッスンで講師が使う場合のため）。既定はオフ。

## 採用3: 判定の救済に上限を付ける（契約の変更）
`judgeNote` の第2段「候補中で目標が最も近ければ正解」には距離の上限がない。候補の最低音より
下・最高音より上は、どれだけ外れていても正解になる。ふよみは音域が G3〜B5 と広いので放置しない。
- **第2段・第3段の救済は、目標から ±250セント以内のときだけ有効**にする。
  それを超えたら救済せず、外れとして「○○の高さに聞こえたよ」を返す。
- 第1段（±tol 以内は無条件で正解）はそのまま。

## 採用4: 始める前に「マイクが音を拾えている」ことを確かめる画面を入れる
最初の1音で進まなかったとき、生徒には楽器・弓・端末・アプリのどれが悪いのか分からない。
- 「はじめる」の直後に**音の確認**を置く。「ラ線（A線）を開放で1回鳴らしてみて」と出し、
  何か音が取れたら「聞こえてるよ」と表示して先へ進む。数秒で終わること。
- 取れないときは、音量・マイクの許可・周囲の音を順に日本語で案内する。ここで止めない
  （「音を聞かずに譜読みだけ練習する」へ落とせる）。

## 採用5: 演奏中に押さなければならないボタンを作らない
バイオリンを構えていると両手が塞がる。譜面台の上のスマホには手が届かない。
- 音が合えば**自動で次へ**。外しても自動で同じ音を続ける。必須の操作はゼロ。
- 「わからない」「とばす」「やめる」は、楽器を下ろしてから押す任意の操作として置く。

## 採用6: 記録するのは事実だけ。原因を自動で診断しない
同じ誤りでも、符頭の位置を読み違えた／調号を忘れた／弦を間違えた／押さえがずれた／
検出器が倍音を拾った、のどれか分からない。
- 残すのは「出題の譜面位置」「検出した音高」「最初の発音までの時間」「やり直し回数」「使ったヒント」。
- 「調号が苦手ですね」のような自動診断は出さない。

## 採用7: 講師が条件を渡せるようにする（URLのクエリ）
`?level=3&key=A&hint=off&n=5` のようなクエリで設定を上書きできるようにする。
講師が生徒に送るリンクで条件を固定できる。アカウントもダッシュボードも作らない。

## 採用8: 音程の点数を出さない
姉妹アプリの「100点」を持ち込まない。譜読みの成否と音程の精度を混ぜると、
何が上達したのか分からなくなる。結果は「何音を、ヒントなしで、一発で通せたか」で表す。
- 「ゆるさ」と「A4の基準」は既定値のまま**詳細設定に畳む**（消しはしない）。既定 loose / 442。

## 却下1: レベル6（4の指）を削る — 却下
4の指は1ポジションの定義そのもの（隣の開放弦と同じ高さになる）で、ここを外すと
1ポジションを教えたことにならない。音高としては正しく判定できる。
- 代わりに、レベル6の説明と、該当する音の注記に
  **「4の指は隣の開放弦と同じ高さ。音では区別できないので、弦は自分で見て確かめて」**と明記する。

## 却下2: フレーズを2音／可変長にする — 却下（保留）
4音のまま固定して実機で測る。第3・第4音だけ反応が悪いというデータが出てから考える。

## 保留: 出題が範囲を履修しない件
セッション内で出る音を均す仕組みは MVP に入れない。代わりに結果画面で
「レベル3 合格」と言わず「**今回出た音**」と書く。嘘をつかないことで凌ぐ。

## 決定: 契約の矛盾を潰す
- 跳躍は **音階上の4度まで、1フレーズに最大1回**（SPEC の「3度まで」は誤り。CONTRACT が正）。
- `LEVELS.span` は**削除**する。意味が定義されていない値を残さない。
- `midiToStaff` の B5 の diatonic は **11**（CONTRACT の 12 は私の書き間違い。E4=0 起点で数え直すと 11）。

# 追加の決定（2026-08-23・コードレビューの結果を受けて）

## 採用9: 判定の候補は「レベルの出題範囲」ではなく「第1ポジションで出せる全部の音」
レビューで再現された実バグ。レベル1（ラ線だけ）で レ5 を出題したとき、生徒が隣の**開放ミ線**を
弾くと、候補にミ5が無いため「候補の中でいちばん近いのはレ5」となり、200セント外れているのに
正解になる。**出題する集合と、聞こえた音を言い当てるための集合は別物。**
- `judgeNote` に渡す `candidates` は、いまの調で第1ポジションから出せる**4弦すべての音**にする。
  （同じ高さは指の少ないほうを代表に1つだけ）
- 出題（`makePhrase`）の範囲はレベルのまま変えない。

## 採用10: 音程の精度で落とさない。落とすのは「別の音を弾いたとき」だけ
このアプリは譜読みの練習であって音程の練習ではない（採用8と同じ理由）。
- 候補が4弦ぶん揃えば、隣の音との間隔は最大でも全音（200セント）なので、
  「いちばん近い候補が目標」＝「読み間違えていない」を意味するようになる。
  多少ぶら下がっていても**読めているなら通す**。
- `RESCUE_MAX_CENTS = 250` はそのまま残す。これは音域の外（ソ3より下・シ5より上）で
  救済が無限に広がるのを止めるためだけの安全弁。

## 採用11: オクターブ救済（第3段）は「オクターブを畳んだ距離」で判定する
レビューで、第3段が**構造的に一度も到達しない**ことが証明された（生の距離が±250以内という
入口を通ると、その時点で第1段か第2段で決着してしまう）。初心者は基音が弱く2倍音を拾うので、
この救済は残す価値がある。
- 第3段の入口を「生の距離が±250以内」ではなく、**オクターブを畳んだあとの距離が
  `cfg.tol` 以内**に変える。第3段が実際に成功する経路をテストで固定する。

## 採用12: 合格・不合格のあとは「いったん途切れる」まで次の判定を始めない
レビューで再現。弓を止めずに伸ばし続けると、同じ持続音が次の問題の答えとして数え直され、
次が違う音なら誤答が、同じ音なら自動合格が記録される。
- 次の音の判定は、**無音区間か新しい弾き始め（オンセット）を観測してから**始める。

## 採用13: 結果画面の主語は音高。運指は従属情報
「ラ線の2（ド♯）で2回やり直した」は、観測していない弦と指を主語にしている（採用1違反）。
- 「**ド♯で2回やり直した（勧めた運指: ラ線の2）**」の形にする。
- 集計のキーも弦と指ではなく**音高**にする。同じ音が別の運指で出題されても1件にまとめる。

## 採用14: app.js に差し替え可能な境界を置き、状態機械をテストする
上の1〜4・6は**テストが全部緑のまま**再現した。純関数だけをテストしていて、
画面遷移・タイマー・マイクを一度も動かしていないため。
- DOM・時計・マイクを差し替えられる小さな境界を `js/app.js` に作り、
  再現した経路（持ち越し・二重予約・おてほん中の記録・結果の文言）を統合テストにする。

# 追加の決定（2026-08-25・作者の指示による改修）

## 採用15: 弦の色と指番号を譜面に出す。既定は「色と指番号」
作者の指示。ゆびいろ（弦の色＋指番号）から来た生徒が、五線譜へ移る段差を小さくするため、
符頭・符幹・加線・臨時記号を弦の色で塗り、指番号を音符の上に出す。

**これは採用2「答えを常時表示しない」と正面からぶつかる。**
色と指番号が出ていれば、五線の高さを読まなくても弾けてしまう。それでも出すのは、
段差の前で止まる生徒のほうが多い、という作者の現場判断による。代償を消す方法は用意した:

- 設定「弦の色と指番号」で **色と指番号 / 色だけ / なし** の3段階。`?marks=off` でも固定できる。
- 「色だけ」は、指番号（＝どこを押さえるか）を消し、弦（＝どの高さの帯か）だけを残す中間段。
- 音名のヒントは従来どおり既定オフのまま。ここは変えない。

判定には一切関わらない。色も指番号も「このアプリが勧める運指」の表示であり、
マイクが観測しているのは音高だけ、という採用1の建て付けは変わらない。

実装上の決めごと:
- 色は `theory.js` の `STRINGS`（ゆびいろと同じ。ソ=青 レ=橙 ラ=赤 ミ=緑）。
  ダーク背景では沈むので、同じ色相で明度を上げた `colorDark` を使う。
- **`state='miss'` のときだけ弦の色を使わない。** ミ線の緑と「合っていた」の緑が
  同じ意味に見えるため。外した音はテーマの miss 色に戻す。
- 指番号は五線の上端より上に一列で置く。音符の上端だけを見て置くと、
  五線の中に入って線と数字が重なる。上加線へ出た音だけが自分の加線ぶん持ち上がる。

## 採用16: レベルを6段から8段へ。1〜4は高い弦から1本ずつ
作者の指示。ミ線 → ラ線 → レ線 → ソ線 の順に1本ずつ覚え、そのあと組み合わせる。

| | 弦 | 指 |
|---|---|---|
| 1〜4 | ミ / ラ / レ / ソ を1本ずつ | 0〜3 |
| 5 | 選んだ2本 | 0〜3 |
| 6 | 選んだ弦（1〜4本） | 4まで |
| 7 | 4本ぜんぶ | 0〜3 |
| 8 | 4本ぜんぶ | 4まで |

- レベル5・6は `LEVELS[n].strings` を `null` にし、`choose:{min,max}` と `preset` を持つ。
  弦の選択は画面（設定の「使う弦」ボタン）から `makePhrase({strings})` へ渡す。
- 本数が `choose` に合わない選択は `preset` へ落とす。画面に見えている弦と出題の弦は必ず一致させる。
- レベル5で3本目を押したら、いちばん先に選んだ弦を外す。押した弦は必ず残る（拒否で止めない）。
- 1本ずつのレベルは加線が増える（ミ線は上第1加線、ソ線は下第2加線）。
  真ん中のラ線から始める従来の順より読む位置は難しくなるが、弦を1本に絞る効果を優先した。

## 採用17: 設定はレベル以外ワンタップ。おてほんは常時オン。合格を耳へ返す
作者の指示（2026-08-25、採用15・16と同日の実機フィードバック）。

- **レベル以外は `select` をやめ、選択肢を出したままボタンで選ぶ。** 開いて選ぶ2手が、
  楽器を持ったまま設定を変える動きに合っていなかった。レベルだけは8段あるので select のまま。
  実装は select を値の置き場として残し（`.visually-hidden`）、チップが value を書き換える形。
  保存・URL上書き・講師リンクの `disabled` は今までの仕組みにそのまま乗る。
- **フレーズ数（既定3）・判定のゆるさ・A4の基準は詳細設定へ畳む。**
- **おてほんの音の設定は消して常時オン。** 切る理由が実際には無かった。
- **1音合格するたびに短い上昇音を鳴らす。** 「集中して弾いていても正解が分かるように」。
  調の主和音を2オクターブ上で分散（第1ポジションの最高音シ5=988Hzより上）なので、
  弾いている音に埋もれず、どの調でも調外の音が鳴らない。最後の音だけは鳴らさない
  （直後の4音そろいの和音が合図になる）。手動モードでも鳴らさない（自分で進めるため）。

## 採用18: 鳴らす音に倍音を重ねる。ミュートは「塞ぐ必要のある音」だけ
「おてほんの音が音程か音質が変。音量も小さい」（作者・実機）。原因はサイン波。

- 基音しか無いので、iPhoneのスピーカーが出せない帯域（およそ200Hz以下）に基音がある
  ソ線・レ線のおてほんが、痩せて音程の分からない音になっていた。
- `createPeriodicWave` で倍音を重ねた（配分は弦楽器の傾向に寄せた概形。実楽器の複製ではない）。
  倍音があれば、基音が再生されなくても倍音列から高さが分かる（missing fundamental）。
  高次のざらつきは基音の6倍あたりのローパスで削る。
- 音量は OfflineAudioContext で実測して決めた。ソ3(196Hz)を300Hzハイパスで測った RMS が
  旧0.020 → 新0.076（約3.8倍）。ピークは0.25前後でクリップしない。
- **`holder.muteUntil()` は、こちらの音を生徒の演奏として数えうる長い音だけに使う。**
  合格音のような短い音で塞ぐと、`muteUntil()` が受付を閉じたまま次の音の判定へ入り、
  弓を止めずに弾き続けた生徒がいつまでも合格しなくなる（テストで再現した）。
- **完了和音のミュートが解けるまで次のフレーズを出さない。** 塞いでいる間に次が始まると、
  1音目の頭が食われて「弾いているのに進まない」になる（これもテストで再現した）。

## 採用19: 調は名前だけで選ばせない。合格の言葉は「聞こえたよ」をやめる
作者の指摘（2026-08-25）。

- **「ハ長調／ト長調／ニ長調／イ長調」だけでは、生徒がどれを選ぶか判断できない。**
  チップに♯の数を添え、その下に **選んだ調の調号を譜面と同じ字形で描く**（`renderStaff` に
  音符を渡さず、ト音記号と調号だけを出す）。譜面のいちばん左に並ぶものと、調の名前を、
  設定画面でそのまま結びつけられる。
- **合格の文言「聞こえたよ。」をやめ、「ばっちり。」「いい感じ。」「その音。」を
  順に回す。** 観測に忠実な言い方ではあったが、弾いた本人には冷たい。
  音程の良し悪しは言わない（採用8）ので、言っているのは「読めていた」ことだけ。
  乱数ではなく記録の本数で選ぶため、順序は決定的でテストからも固定できる。
- ついでに、`?cb=` のような無関係なクエリで「先生の指定で始めます」が出ていたのを直した。
  効いた指定（locked かstrings）があるときだけ出す。
